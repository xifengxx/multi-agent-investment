# 当前阶段进度梳理（到 L4）与下一阶段任务清单（P3 从 A 开始）

## 1. 目标框架（用户 5 步）

1️⃣ 数据处理：Excel → 读取 → 合并总表 → 写入 Bitable  
2️⃣ 7 大 LLM 分析：并行调用 → 建仓建议 + 置信度  
3️⃣ 汇总决策：投票筛选（≥4 入选）→ 置信度加权 → 输出 10–20 清单  
4️⃣ 模拟交易：推送 Telegram → AI 自动执行 / 人工执行 → 记录持仓  
5️⃣ 周度复盘：评估表现 → 评估 LLM 准确率 → 调仓建议  

结合阶段划分：

- 第一阶段目标：做到 L4（即 1–4 跑通闭环即可）
- P0（定时器）：不做（因模拟交易与收益评估不完整，L5 暂不具备价值）
- P1/P2：先保持原状（先跑一段时间，再扩模型与优化加权）
- P3：产品化入口与扩展（下一阶段重点），从 A（Web 上传入口）开始

## 2. 现状对齐：系统已具备 / 缺失点

### 2.1 数据处理（1️⃣）

已具备：
- Excel 文件命名契约校验（stock+etf 成对）
- Excel 读取与字段解析
- SQLite 审计与回放：runs/file_batches/instrument_snapshots

缺失（对齐“合并总表 + Bitable”）：
- stock_master/etf_master 的“总表/当前视图”概念未落地（当前偏批次审计事实库风格）
- Bitable（飞书表格）写入未实现

### 2.2 LLM 分析（2️⃣）

已具备：
- L3 已按“按文件面板整体分析（panel）”实现（每 provider 每文件一次）
- 支持多 provider + 运行期降级
- 支持“附件优先 → 摘要回退”混合链路，贴近网页端上传附件的使用体验

缺失：
- 不同 provider 对“文件输入”的能力差异仍存在，需要通过 overrides 与回退策略稳定运行

### 2.3 汇总决策（3️⃣）

已具备：
- 将每份报告的 Top10 展开为 llm_outputs 票源
- Voting → decisions 落库

缺失（按最初规则）：
- ≥4 票必入选 / 3 备选 / 2 次选 的严格门槛目前为“联调友好”模式（后续再收紧回归）
- 置信度加权尚未实现（属于 P2）

### 2.4 模拟交易（4️⃣）

已具备（最小版）：
- decisions → paper_trades/positions 写入（内部 SQLite 账本）
- Telegram 推送与通知落库（发送失败不影响 run 完整落库）

缺失（对齐“AI 自动执行 / 人工执行 / 模拟交易软件”）：
- 缺少“执行工作流”（确认/拒绝/重复执行保护/撤销等）
- 缺少外部“模拟交易软件”对接适配器（目前只内部账本）

### 2.5 周度复盘（5️⃣）

现状：
- 已有 weekly_run 与基础统计（基于 paper_trades）

为何暂不做 P0 定时器：
- 缺少行情/收益回撤，无法做你想要的“评估 LLM 准确率 → 调仓建议”的核心闭环
- 因此将第一阶段定义为“到 L4”是合理的阶段拆分

## 3. 当前阶段结论（第一阶段是否完成）

第一阶段（到 L4）的关键判定标准：
- daily 跑通：能产生 llm_reports/llm_outputs/decisions/paper_trades，并能推送或至少记录 notifications
- 能回放审计：按 run_id 查到输入文件批次与 LLM 原始输出/报告

当前结论：
- 第一阶段闭环已可运行；并通过“附件优先 + 摘要回退 + provider 输入模式覆盖”实现稳定性。

## 4. 下一阶段（P3）任务清单（从 A：Web 上传入口开始）

> 目标：把现有“本地投递 + CLI 触发”的流程产品化为“上传 → 校验 → 运行 → 查看结果”的可视化入口。

### P3-A1：最小 Web 上传入口（MVP）

功能：
- 页面上传两份文件（stock/etf）
- 校验命名契约与基本字段
- 上传成功后触发一次 daily（或生成可点击的“开始运行”按钮）
- 展示 run_id 与当前状态（RUNNING/SUCCEEDED/DEGRADED/FAILED）

验收：
- 上传错误（缺一份/命名不对/字段不齐）能明确提示
- 上传正确后能在 SQLite 看到 file_batches 与 runs 记录

### P3-A2：运行结果页面（最小可用）

功能：
- 列表页：最近 N 次 runs（snapshot_date、status、run_id、开始/结束时间）
- 详情页：
  - decisions（stock/etf 分开 Top10）
  - reports：链接到对应的 Markdown 报告文件（或直接渲染）
  - notifications：本次推送状态与失败原因（若失败）

验收：
- 能从页面定位到某一次 run 的所有产物（清单+报告+通知状态）

### P3-A3：上传文件与数据的“当前视图”层（为 Bitable 铺路）

功能：
- 明确“同一 snapshot_date 的最新批次”概念（可作为查询默认）
- 提供按 snapshot_date 查询最新 batch 的接口

验收：
- 多次上传同一天数据，不会混乱：页面能明确展示“最新一次上传”的批次

### P3-A4：安全与运维最小集

功能：
- Web 入口鉴权（最小：本地口令/单用户 token）
- 日志与错误可观测（页面可见错误摘要，详细错误入库）

验收：
- 不会暴露 token/key
- 页面错误不导致 runs 悬挂
